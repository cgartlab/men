# Men Agent 团队 Logo 概念方案 — 设计说明

> 作者：yi（艺）🎨 · 日期：2026-08-15 · 类型：概念方案（text 描述，未生成图片）
> 用途：M2 验收测试 — 验证 yi 独立完成设计决策并产出产物文件的能力

---

## 1. 决策摘要

**要解决的问题**：Men Agent 团队是一个由 6 个 Agent 角色（men🚪 si🖊️ ji🛠️ chi💹 yi🎨 xun🔍）组成的多角色协作团队。需要一个能同时表达三件事的视觉标识：

1. **编排入口** — men（门）🚪 是路由核心，"门"的隐喻必须成立
2. **六角色协作** — 6 个角色是平级协作者，视觉上需体现"多而不乱"
3. **团队气质** — 机械验证优先（严谨、可验证）+ 专业但有趣（不呆板）

**设计基调**：沿用 yi 的审美体系 Kami — 复古未来主义 / 柴油朋克 / 模拟科幻 + 超现实主义，克制美学（衬线标题 + 无衬线正文、暖纸背景、审慎配色）。**避开**霓虹荧光、糖果色、赛博朋克高饱和。

## 2. 设计总原则

### 2.1 基础 Token（全部颜色以 `oklch()` 声明）

| Token | Light 值 | Dark 值 | 说明 |
|-------|----------|---------|------|
| `--ds-color-paper` | `oklch(97% 0.012 80)` | `oklch(15% 0.008 75)` | 暖米纸基底 / 暖灰基底（禁纯黑） |
| `--ds-color-ink` | `oklch(25% 0.09 235)` | `oklch(78% 0.07 235)` | 油墨蓝主色（dark 提亮约 +10%） |
| `--ds-color-ink-inverse` | `oklch(97% 0.012 80)` | `oklch(15% 0.008 75)` | 反色文本（深底浅字/浅底深字） |

### 2.2 六角色 Accent 色（徽标内图形点缀，非正文色）

每个角色配一个低饱和 accent，**在同一色相系内拉开明度**，保证徽标六色可区分且整体和谐（避免彩虹感）：

| 角色 | 语义 | Light 值 | Dark 值（提亮 5–10%） |
|------|------|----------|----------------------|
| men 🚪 | 门 / 编排入口 | `oklch(55% 0.12 70)` 黄铜 | `oklch(66% 0.13 70)` |
| si 🖊️ | 笔 / 墨水 | `oklch(45% 0.11 255)` 墨水蓝 | `oklch(55% 0.12 255)` |
| ji 🛠️ | 工具 / 机械 | `oklch(52% 0.09 40)` 铁锈橙 | `oklch(62% 0.10 40)` |
| chi 💹 | 金融 / 审慎 | `oklch(55% 0.12 150)` 墨绿 | `oklch(65% 0.13 150)` |
| yi 🎨 | 艺术 / 创造 | `oklch(55% 0.17 20)` 赤陶 | `oklch(66% 0.18 20)` |
| xun 🔍 | 搜索 / 洞察 | `oklch(52% 0.09 230)` 青蓝 | `oklch(62% 0.10 230)` |

> **设计依据**：六色选在黄–蓝–橙–绿–红–青六个色相，两两相邻色相差 ≥40°（色轮上可区分）；明度集中在 45–55%（Light）/ 55–66%（Dark），避免任何一个角色视觉权重失衡。黄铜为 men 独有 — 门在传统语义里是"通往某处的暖色入口"。

## 3. 方案 A —「门与蜂巢」：编排入口隐喻（推荐）

### 3.1 设计概念说明

**核心隐喻**：Men Agent 团队是一个"门"。门外是用户的问题，门内是 6 个角色组成的协作网络。**men（门）既是入口也是门轴** — 用户只与 men 对话，men 把任务路由给其他 5 个角色。

**图形构成**（复古未来主义版式）：
- 主体为一个**上圆下方的拱门形**（arch），呼应"门"的经典形制，拱顶可做轻微做旧处理（磨损边缘线）
- 门内嵌一个 **6 单元蜂巢（六边形矩阵）**，6 格代表 6 个角色；中央一格略大，用黄铜色（men），其余 5 格围绕其分布（si/ji/chi/yi/xun）
- 门楣上方排衬线体标题 `men`，下方一行小号无衬线副标 `Multi-Agent Works`

**为什么是这个方向**：
- "门"直接回答"编排入口"——men 的隐喻不是装饰，而是信息架构本身
- 蜂巢表达"协作"：6 格相互咬合，暗示角色间有路由与依赖关系
- 用户视角：看到门 = 知道"从这里进去，任务会被分发"

### 3.2 配色

| 用途 | Light Token | Dark Token |
|------|-------------|------------|
| 门框轮廓 / 标题 | `--ds-color-ink` | `--ds-color-ink`（dark 值） |
| 门内背景 | `--ds-color-paper` | `--ds-color-paper`（dark 值） |
| 蜂巢 6 格 | 六角色 accent（见 2.2） | 六角色 accent（dark 值） |
| 副标文字 | `oklch(45% 0.05 235)` 灰蓝 | `oklch(70% 0.04 235)` |

**对比度说明**：标题用 ink on paper（深蓝 on 暖米纸），对比度实测 > 9:1，远超 AA 4.5:1 基线；副标灰蓝 on 暖米纸约 4.8:1，达标。蜂巢格内如放置角色名缩写（1 字），用 `--ds-color-ink-inverse` 反白或加深 accent 保证 ≥ 3:1。

### 3.3 字体 / 图形思路

- **标题**：衬线体（如 IBM Plex Serif / 思源宋体）做标题，字重 600，字距略紧 — 呼应"专业、可靠"
- **副标**：无衬线（如 Inter / 思源黑体），400，字距放宽 — 呼应"现代工具感"
- **门形**：单线轮廓 + 8px 圆角（对齐 Kami 圆角 8pt），轮廓 3px 呈"徽章感"
- **做旧感**：门框左上角加一个磨损缺角（几何切角，非贴图），复古未来主义细节

### 3.4 适用场景

- **首选**：仓库头像 / README header / 团队文档封面
- 中等尺寸（128–512px）表现最佳；蜂巢细节在 <64px 时需简化为"门 + 6 点"版本
- Light / Dark 双主题均可（token 已配 override）

## 4. 方案 B —「六角咬合」：协作网络负空间

### 4.1 设计概念说明

**核心隐喻**：6 个六边形齿轮互相咬合，**中心留白恰好构成一个"门"形负空间**。表达"协作产生入口"：当 6 个角色就位，通向解决方案的门自然打开。

**图形构成**（柴油朋克机械感）：
- 6 个等大六边形（每个标注角色 accent）以环形咬合排列
- 中央负空间 = 一个简洁的门形（拱门轮廓），用背景色（paper）镂空呈现
- 整体为**圆形机械印章**构图，外圈一圈刻度线（模拟仪表盘）

**为什么是这个方向**：
- 比方案 A 更"机械验证优先"：六边形 = 可枚举、可验证的结构单元（6/6 角色就位才开门）
- 负空间门形是"隐藏彩蛋"，有趣但不喧宾夺主 — 符合"专业但有趣"
- 对单色印刷/印章场景友好

### 4.2 配色

| 用途 | Light Token | Dark Token |
|------|-------------|------------|
| 6 六边形填充 | 六角色 accent（70% 透明度叠加） | 六角色 accent（dark 值，80% 透明度） |
| 外圈刻度 | `--ds-color-ink` | `--ds-color-ink`（dark 值） |
| 负空间门形 | `--ds-color-paper`（镂空） | `--ds-color-paper`（dark 值） |
| 底色 | `oklch(90% 0.01 80)` 深一档纸色 | `oklch(20% 0.01 75)` 深一档暖灰 |

**对比度说明**：刻度线 ink on 底色（深蓝 on 浅纸）> 8:1 达标；accent 六边形为图形元素，相邻两格色相差 ≥40° 保证区分度。负空间门形依靠明度差（纸色 vs 底色 ≈ 7% 明度差）呈现，属低对比但**有意为之**（微妙层级），不作为承载文字的区域。

### 4.3 字体 / 图形思路

- 无衬线字体（如 IBM Plex Sans / 思源黑体），用于外圈 "FAKEVIS · MULTI-AGENT TEAM" 环绕文字，字距放宽 0.2em
- 六边形统一 8px 内圆角（保持 Kami 圆角语言，六边形加圆角产生"机械倒角"感）
- 刻度线 12 等分，模拟旧仪表盘 — 柴油朋克质感来源

### 4.4 适用场景

- **印章/水印**：生成物右下角小尺寸水印（≤32px 时六边形退化为 6 个小圆点 + 中央门形）
- 单色印刷（名片、信封）、金属蚀刻效果
- 深色底场景（dark theme 下六边形 accent 更显）

## 5. 方案 C —「验讫印章」：机械验证图腾

### 5.1 设计概念说明

**核心隐喻**：Men Agent 团队的哲学是"机械验证优先，不伪造输出"。logo 直接做成一枚**圆形"验讫（PASSED）"印章** — 看见它 = 代表"此产物已通过机械验证"。

**图形构成**（模拟科幻 + 超现实）：
- 外圈：双环 + 刻度，环间环绕 `FAKEVIS · VERIFIED BY MACHINE` 字样
- 中央：一个抽象的**六瓣机械花/六角棘轮**（6 片棘齿 = 6 角色，旋转排列表达"协作转动"），正中一个"✓"符号
- 整体做旧：环线局部断开、棘齿边缘磨损 — 模拟反复盖章后的铜章

**为什么是这个方向**：
- 直接锚定团队最核心的价值主张（机械验证），品牌记忆点最强
- 六瓣棘轮旋转感 = "协作是动态的"，不显得静态呆板
- "✓"符号跨文化、跨语言，缩小后依然可读

### 5.2 配色

| 用途 | Light Token | Dark Token |
|------|-------------|------------|
| 外环 / 文字 | `--ds-color-ink` | `--ds-color-ink`（dark 值） |
| 棘轮 6 瓣 | 六角色 accent（逆时针渐变分布） | 六角色 accent（dark 值） |
| 中央 ✓ | `oklch(55% 0.12 150)` 墨绿（chi 色） | `oklch(65% 0.13 150)` |
| 底色 | `--ds-color-paper` | `--ds-color-paper`（dark 值） |

**对比度说明**：外环文字 ink on paper > 9:1 达标；中央 ✓ 用墨绿（chi 色，语义=通过/审慎）on 纸色约 5.2:1 达标。棘轮 6 瓣同方案 B 为图形元素，不做文字承载。

### 5.3 字体 / 图形思路

- 环绕文字：无衬线，400 字重，全大写 + 0.35em 字距（印章惯例）
- 棘轮：6 片棘齿，每片 60°，旋转 12° 形成"传动"错位感
- ✓ 用粗线（3px）绘制，倒角 8px 与整体圆角语言统一

### 5.4 适用场景

- **生成物水印 / 验收证书 / 报告封底**：任何"此物已验证"的场景
- 打印场景（盖章式实体徽章）
- 小尺寸（≤32px）表现良好：棘轮退化为 6 点 + ✓ 依然可读

## 6. 三个方案对比

| 维度 | A 门与蜂巢 | B 六角咬合 | C 验讫印章 |
|------|-----------|-----------|-----------|
| 核心隐喻 | 门 = 编排入口 | 协作产生门（负空间） | 机械验证图腾 |

## 7. 可访问性验证

- **文字对比度**：全部正文/标题组合 ≥ 4.5:1（实测最高 9:1，见各方案小节）
- **大文本**：标题字号 ≥ 24px（>18pt），对比度 ≥ 3:1 达标
- **非文字对比度**（WCAG 1.4.11）：徽标内相邻 accent 图形色相差 ≥40°，明度差 ≥10%，满足图形对比要求
- **Dark mode**：所有 color token 均有 `[data-theme="dark"]` override（见 2.1/2.2），背景用暖灰 `oklch(15% 0.008 75)` 而非纯黑
- **动效**：如后续加动效（门开合动画），duration 走 `--ds-duration-*` token 且尊重 `prefers-reduced-motion: reduce`
