**原始设计依据口径**（对 V6 的约束）：

- 「原始设计」= **用户口述的初始架构蓝图**（来源：本分析任务输入中的「用户最初的架构设想」六要点），非仓库文件记载
- 「当前实现」= 仓库文件可验证事实（agent 定义 / PRD / architecture.md 等）
- 两者来源不同源：口述蓝图 ≠ 文档事实。凡「原始设计」条目均标注依据；**口述与文档不一致处显式标存疑**（本报告仅偏离 4 存在该情况）

## 一、偏离清单

### 偏离 1｜拓扑层级：两级 → 扁平

- **原始设计（依据：用户口述）**：两级拓扑。Men 顶层路由，Si 中间层"拆解/推理/评估"，向下分派 Ji/Yi/Chi；Men 直连 Xun。
- **当前实现**：Men 唯一 spawner，5 个 subagent 扁平直连，**禁止互相 spawn**（D2）。
- **偏离程度**：**重大**
- **功能意图是否保留**：部分保留。
  - Si 的"拆解"→ 保留为 plan envelope（plan-compose）
  - Si 的"编排分派"→ 上收至 men（混合任务拆分规则 + Wave）
  - Si 的"质量评估"→ 移交双层验证（verify.mjs 机械 + chi fresh-context）

### 偏离 2｜Si 角色：拆解/推理/评估 → 规划/写作

- **原始设计（依据：用户口述）**：Si = 拆解/推理/评估大脑，评估结果回传 Men。
- **当前实现**：Si = planner + writer + 知识管理（si-plan-compose / si-content-write / si-knowledge）。
- **偏离程度**：**重大**
- **功能意图是否保留**：部分保留。"拆解"保留完整；"评估"被双层验证替代（更客观）；"写作"是新增职责。

### 偏离 3｜Chi 角色：状态/记忆/沉淀 → 投资 + judge

- **原始设计（依据：用户口述）**：Chi = 状态/记忆/沉淀，状态回传 Men。
- **当前实现**：Chi = 投资分析 + 独立 Judge；状态/记忆/沉淀由「events.jsonl 事件审计 + knowledge/ 知识库 + learn.mjs 学习回路」替代（D9/D13）。
- **偏离程度**：**重大**
- **功能意图是否保留**：实质保留，但**载体改变**——从"人肉 LLM 记忆"换成"机械文件 + 事件流"。这是全报告**最重要的一次替代**。

### 偏离 4｜Ji 角色：通用执行者 → 纯代码

- **原始设计（文档口径）**：Ji = 通用执行者（developer，主执行）。依据 PRD.md 角色表（前端实现、GitHub 操作、L1 机械验证、目录结构审计）与 m0-synthesis.md「ji = developer（主执行，L1 检查器优先）」，**均无写作职能记载**。
- **存疑标注**：用户在初始架构设想中口述「Ji = 写作/代码（两者都做）」（依据：用户口述）。该条与文档口径**不一致**——写作职责是否曾属 ji 存疑；PRD.md 与 m0-synthesis.md 均将 ji 定义为纯工程 developer。**若用户确认初始设想确含写作，以用户口述为准**；若按文档口径，ji 从未承担写作，此条不构成"职责移出"。
- **当前实现**：Ji = 纯代码工程（HTML/CSS/JS 优先）；写作由 Si 承接。
- **偏离程度**：**中度（建立在用户口述之上）**
- **功能意图是否保留**：写作职责完整移交 si（si-content-write + si-knowledge 技能）；无论按哪一口径，ji 当前均为纯代码角色，文档与实现一致。

### 偏离 5｜质量评估回传：Si 自评回传 → 双层验证

- **原始设计（依据：用户口述）**：Si 评估质量 → 回传 Men。
- **当前实现**：verify.mjs 五项机械检查 → chi fresh-context 独立 judge → gate 事件（D3/D4）。
- **偏离程度**：**重大**
- **功能意图是否保留**：是，但「评估者」从 si（执行链同源）换成 chi（fresh-context 独立）；「评估方式」从 LLM 判断换成机械优先。

### 偏离 6｜状态回传：Chi 主动回传 → 事件留痕（写后不读）

- **原始设计（依据：用户口述）**：Chi 状态回传 Men（主动反馈）。
- **当前实现**：各 agent 写 `judge`/`verify`/`dispatch`/`handoff` 事件到 events.jsonl（best-effort）；men 汇总后触发 learn.mjs。
- **偏离程度**：**中度**
- **功能意图是否保留**：**部分缺失**。留痕完整，但**"回读/回流"环节弱**——详见第四节闭环缺口。

### 偏离 7｜Xun 挂载：Men 直连

- **原始设计（依据：用户口述）**：Xun 独立挂 Men 下。
- **当前实现**：Xun 也是 men 直接 spawn。
- **偏离程度**：**无偏离**（与原始一致）

## 二、按用户三项优先级评估

> 优先级：**① 质量 ② 效率 ③ 成本**。以下仅对偏离 1-6 逐条评估。

### 偏离 1｜扁平拓扑 vs 两级拓扑

| 维度 | 影响 | 理由 |
|------|------|------|
| 质量 | **正面** | 扁平拓扑下验证去中心化：不是"拆解者评估自己的拆解"（自评偏差），而是机械脚本 + fresh-context 独立 judge（D3 拒绝 LLM 自评，M0 调研明确结论） |
| 效率 | **正面** | 少一跳：两级拓扑每轮多一次 si 中间调度往返 + 串行瓶颈；扁平拓扑 Wave 并行直达 |
| 成本 | **正面** | 只 spawn 需要的角色，si 只在 team/hyperplan 时介入；中间层全流程托管会显著增加 LLM 调用量 |

**关键判断**：若恢复原始两级拓扑（Si 中间编排层）——**质量中性偏负**（自评链条 + si 是 flash 模型、judge 能力弱于 chi 的 glm-5.2）；**效率负**（多一跳 + 串行）；**成本负**（全流程多一层调用）。且 OpenCode 的 subagent 定义层**不支持嵌套 spawn**，恢复需改插件机制，工程成本高。

### 偏离 2｜Si 角色变化

| 维度 | 影响 | 理由 |
|------|------|------|
| 质量 | **正面** | 规划与写作合并到"内容大脑"：plan 与文章风格同源；评估职责剥离后 si 不再自评，消除利益冲突 |
| 效率 | **正面** | 写作任务直路由 si，不再经过编码 agent；规划复用 plan envelope 模板 |
| 成本 | **中性** | si 用 sensenova flash 系，写作/规划成本低；评估职责移交虽省 si 调用，但 chi（glm-5.2 较贵）仅在 analyze/team 触发 |

### 偏离 3｜Chi 角色变化（最重要）

| 维度 | 影响 | 理由 |
|------|------|------|
| 质量 | **正面** | LLM 人肉记忆是「易失、主观、不可审计」；events.jsonl 是「append-only、可回放、可机械验证」（D9）；learn.mjs 将事件流结构化沉淀为 errors/patterns——沉淀质量高于 agent 内存在 |
| 效率 | **正面** | 状态查询变机械操作（event.mjs list/replay），不占用 LLM 上下文；chi 专注投资 + judge 两个高价值职能 |
| 成本 | **正面** | 记忆不再每次任务全量携带（省上下文 token）；事件写入 best-effort 几乎零成本 |

**关键判断**：chi 从"状态/记忆"改为"投资+judge"**是对原始设计的升级而非降级**——原始把"记忆"压在单一 agent 上，是脆弱设计；当前用文件系统 + 学习回路，符合 M0"机械优先"哲学。**唯一短板是"学习不回流"（见第四节）**。

### 偏离 4｜Ji 角色变化

| 维度 | 影响 | 理由 |
|------|------|------|
| 质量 | **正面** | 写作（.md 无 gate）与代码（typecheck/lint/test 强制）执行模式不同，合并会使 ji 的验证铁律误伤写作、或让写作绕过 gate 污染纪律 |
| 效率 | **正面** | 编码 agent 不必切换上下文到写作模式；si 直接 concurrency 承接内容任务 |
| 成本 | **中性** | 写作从 ji 移到 si，均为 flash 系模型，成本相当 |

### 偏离 5｜质量评估机制变化

| 维度 | 影响 | 理由 |
|------|------|------|
| 质量 | **正面（最大收益点）** | 从"执行链同源自评"→"fresh-context 独立复核 + 五项机械检查"（D4）；chi judge 逐条机械核对，PASS/FAIL/REGRESSED/BLOCKED 四态 + 每轮复验防回归 |
| 效率 | **负（轻微）** | 多一道 chi 复核；但 verify.mjs 先免费过滤、chi 只复核通过项，净增延迟可控 |
| 成本 | **中性偏负** | chi（glm-5.2）是团队最贵模型；但仅在 analyze/team 触发 + 机械层先行过滤，杠杆合理 |

### 偏离 6｜状态回传机制

| 维度 | 影响 | 理由 |
|------|------|------|
| 质量 | **负（缺口）** | 事件留痕完整但**写后不读**：men 的路由/规划决策不消费 patterns/errors，学习回路未形成闭环（详见第四节） |
| 效率 | **负（轻微）** | 每次任务都重新"从零开始"规划，未复用历史 pattern |
| 成本 | **负（轻微）** | 重复犯历史错误 = 重复验证轮次 = 重复 LLM 调用 |

### 质量总评：当前扁平拓扑 vs 原始两级拓扑

**当前实现质量更优**，依据（排序按优先级）：

1. **验证链更客观**：双层验证（机械 + 独立 judge）替代 si 自评，M0 调研 D3 已拒绝 LLM 自评
2. **职责边界更清晰**：si 规划/写作、ji 代码、chi 验证、xun 研究，单一职责减少角色冲突
3. **记忆更可靠**：文件系统 + 事件流替代单 agent 内存，可审计、可回放、可机械验证
4. **风险点**：si 的 plan 产物尚无独立判据（chi judge 验证类型表面向代码产物）——见第四节缺口 2

## 三、结论：保持当前 + 补缺口（混合方案）

**推荐：混合方案——保持当前扁平拓扑与角色分工，按第四节补齐回传/凝练闭环。**

理由（对应用户优先级）：

| 问题 | 回答 |
|------|------|
| 恢复两级拓扑？ | **不恢复**。质量负（自评链 + 弱模型评估）、效率负（多一跳）、成本负（多调用）、工程成本高（改插件机制） |
| 保持扁平拓扑？ | **保持**。质量/效率/成本三项全优于原始；D2 是有依据的主动决策 |
| chi 替代方案更优？ | **是**，但必须补「学习回流」缺口，否则 M7 学习回路只是"审计工具"而非"学习系统" |
| ji 拆写作给 si 更清晰？ | **是**（按用户口述口径）。验证纪律与写作模式分离，职责单一化；文档口径下 ji 本就无写作职责，无"拆"可言 |

### 保留当前实现的部分

- **Men 唯一 spawner + 扁平路由**（D2）— 不动
- **Si = 规划 + 写作**（不恢复中间编排层）— 不动
- **Ji = 纯代码**（不恢复写作职责）— 不动
- **Chi = 投资 + judge**（不恢复人肉记忆角色）— 不动
- **双层验证**（D3/D4）、事件审计（D9）、学习回路（D13）— 机制保留

### 需要补强（回传/凝练闭环）的部分

详见第四节 5 条改进建议。**这是混合方案的实质内容：结构不动，机制补闭环。**

## 四、回传机制与凝练机制的缺口分析

### 4.1 已覆盖的回传机制

| 回传方向 | 机制 | 载体 |
|----------|------|------|
| agent → men（质量） | chi judge PASS/FAIL/REGRESSED/BLOCKED + gate 事件 | events.jsonl + judge 报告 |
| agent → men（状态） | dispatch / handoff / verify / judge 事件 | events.jsonl |
| men → 用户 | 四段汇总报告（结论/关键信息/来源/未决） | men.md 模板 |
| 经验沉淀 | learn.mjs → knowledge/errors/ + knowledge/patterns/ | 文件系统 |
| KPI 评估 | eval-metrics.mjs → 8 项指标 | JSON 输出 |

### 4.2 缺口清单

**缺口 1｜学习不回流路由/规划决策（最核心）**
- men 的路由判定表、意图门是**静态写死规则**；learn.mjs 产出的 patterns/errors **没有任何机制让 men/Si 在下次任务时读取**。
- 表现：学习"写入了"，但"应用"环节缺失——相当于学了不进脑子。
- 位置：men.md 意图门（§1）、si.md 规划流程（§2）均无 patterns 输入步骤。

**缺口 2｜si 的 plan 产物无独立判据**
- chi.md 验证类型表（tests/build/file exists/command output/lint/typecheck）全面向**代码产物**；plan envelope 是语义产物（依赖图合法性、波次可并行性、验收标准可测性）无专门标准。
- 表现：团队里"谁的产出最无校验"——答案是 si 的 plan。
- 位置：chi.md 核心职责「独立 Judge」节、skill chi-judge。

**缺口 3｜状态回传是"写后不读"**
- events.jsonl 是 append-only 留痕；men 路由时不查询历史会话结果（`event.mjs list` / KPI JSON 未被路由引用）。
- 表现：事件是"审计证据"，不是"决策反馈"。

**缺口 4｜si 写作产物的 ✅/⚠️/❌ 事实标注不沉淀**
- si 的三级标注只存在于单篇产物，无自动归档进 knowledge/ 的机制，无法复用到后续写作。
- 位置：si.md 事实核查输出节。

### 4.3 可落地改进建议（机制 → 文件/命令）

| # | 建议 | 具体落地 | 优先级 |
|---|------|----------|--------|
| R1 | **路由预检读 patterns**：men 在 triage 低置信分支前先读 knowledge/patterns/ | men.md「任务 triage」节加一步：`read knowledge/patterns/` 检索类似历史；或新增 rules 脚本 `scripts/route-hint.mjs`（输入意图关键词 → 输出匹配 pattern） | P0 |
| R2 | **学习自动转化为门禁规则**：错误模式出现 ≥N 次 → verify.mjs 自动新增检查项 | learn.mjs 增加 `--apply` 模式：把高频错误（如"漏 dark mode override"）写为 `scripts/rules-generated.mjs`，verify.mjs 引入该文件 | P0 |
| R3 | **chi 增加 plan judge 标准** | chi.md 验证类型表新增「plan envelope 评审」类型：依赖图无环、每任务有 QA、波次可并行性论证、验收标准可机械测试；chi-judge SKILL.md 增加 plan-review 节 | P1 |
| R4 | **KPI 落盘供路由参考** | eval-metrics.mjs 输出 `.agents/state/learn/kpi-latest.json`；men 路由判定表低置信分支引用："参考近期 10 次任务通过率，某路由通过率 <80% 则降置信" | P1 |
| R5 | **si-knowledge 强制引用 patterns 索引** | si.md「知识库管理」职责加硬约束：规划/写作前先加载 `knowledge/patterns/index.md`（指向关键 pattern 清单）；si-knowledge SKILL.md 增加引用节 | P2 |

**优先级逻辑**：R1/R2 解决"学习不回流"核心闭环（P0）；R3 解决"plan 无人验收"质量缺口（P1）；R4/R5 是增强型沉淀（P1/P2）。
